# MyLibrary

MyLibrary 是一个本地优先的 Android 个人文化档案库，用于管理书籍、电影、阅读/观看记录、标签和自定义字段。

## 当前范围 — Round 4E

- 新增、编辑、查看、搜索和软删除书籍与电影
- 管理文本、数字、日期和布尔类型的动态字段
- 管理两级标签和数据库状态，并按标签、当前状态筛选资料库
- 通过 Android Photo Picker 保存应用内部原图和缩略图
- 在书架、列表、纯图三种资料库视图间切换
- 使用 DataStore 保存资料库视图及最多四个列表展示字段
- 通过可滑动的同级 Pager 和 MyThings 几何规格的悬浮底栏切换四个主页面
- 所有二级页面使用统一 220ms 纯水平转场；年历是接收年月参数的独立路由
- 在所有主页面显示全局新增作品按钮
- 记录连续的阅读/观看过程；Record 只保存日期、评分、评价和创建时间
- 月历按记录的起止日期生成包含首尾日期的封面投影
- 时间轴按 Record 的创建时间显示；每条记录只出现一次
- 周/月月历作为独立浮层覆盖时间轴，使用双锚点拖动与带迟滞的全年触发
- 时间轴滚动同步首个可见日期，月历点击只精确定位实际存在的完整日期组
- 统一月历、年历、时间轴、资料库与详情页的封面显示策略
- 将当前资料库筛选结果导出为完整封面的高清网格海报
- 编辑页维护多条 Record 草稿，并与作品、状态、标签和字段一次事务保存
- 作品创建日期可用于历史补录；修改后的日期按本地中午保存
- 新增、编辑和详情页使用统一的语义主题、卡片与底部悬浮胶囊

回收站恢复、自定义作品类型、摘录、文字报告导出和统计计算仍留待后续轮次。

## 架构

```text
Compose UI
    → ViewModel
    → Use case
    → Repository
    → Room DAO
```

Compose 不直接访问 Room。数据实体会在 Repository 层映射为领域模型和查询投影。

## 数据库

Room schema version：**7**

主要版本变化：

- v4：`items.current_status_id` 保存作品当前状态；`records.status_id` 继续保存每次记录的历史状态。
- v5：`activities` 建立唯一 `(item_id, date)` 索引，并按 Record 起止日期重建包含首尾日期的月历投影。
- v6：`records.created_at` 保存记录创建时间，并建立查询索引。新记录写入当前时间，编辑记录保持原创建时间。
- v7：移除 `records.status_id`。作品状态只由 `items.current_status_id` 表示，既有 Record、创建时间和 Activity 外键关系均由迁移保留。

`MIGRATION_5_6` 会把旧记录的 `created_at` 回填为其开始日期在本地时区的中午 12:00。选择中午可以降低历史日期在时区转换时跨日的风险，同时让旧记录获得稳定、可解释的时间轴顺序。

`MIGRATION_6_7` 通过重建 `records` 表移除状态列，并在迁移期间备份、恢复 `activities`，保留已有记录及月历投影关联。

所有 Migration 均已注册，未启用 destructive migration。导出的 schema 位于 `app/schemas`。

## Activity 与时间轴契约

Activity 只服务月历：

- 只有开始日期时生成一天。
- 同时有开始和结束日期时，生成包含首尾日期的连续范围。
- 同一作品的重叠记录不会在同一天重复生成月历项。
- 新增、编辑、删除 Record 时在 Room 事务中重建作品的 Activity 投影。

时间轴直接查询 Record：

- 以 `created_at` 的本地日期分组。
- 日期组按日期升序，组内记录按 `created_at`、Record ID 升序稳定排列。
- 修改开始/结束日期不会移动时间轴位置。
- 删除 Record 后，对应时间轴条目同步消失。

时间轴首次进入定位到第一条不早于今天的日期；若全部为历史记录则定位到最后一组。月历手动切月只改变显示月份，保留完整选中日期且不移动时间轴；只有点击存在的完整日期组时才平滑定位。

## 作品创建日期

创建日期继续复用 `items.created_time`，Room 仍为 v7：

- 新增作品默认今天，保存为本地时区中午 12:00。
- 可以在保存前选择任意历史日期。
- 编辑时如果日期未变，保留数据库原始时间戳的全部精度。
- 只有日期实际改变时，才把新日期转换为本地中午时间戳。
- 创建日期与 Record、`Record.created_at`、Activity 和时间轴排序完全独立。

## 状态契约

`items.current_status_id` 是唯一的作品状态来源，用于详情展示和资料库筛选。

Record 不保存状态。新增、修改或删除 Record 都不会更改 `items.current_status_id`；作品状态只在编辑作品时由用户显式保存。

作品编辑页维护完整的 Record 草稿列表。底部记录弹窗的“完成”只更新草稿，最终“保存”才在同一个 Room 事务中统一提交作品基本信息、当前状态、标签、动态字段以及 Record 的新增、修改和删除。原有 Record 被编辑时保持 `created_at` 不变；Record 草稿没有变化时跳过 Record 写入和 Activity 重建，因此单独修改作品创建日期不会触碰二者。

## 图片存储

Photo Picker 选中的封面会写入应用内部目录：

```text
images/
├── original/<id>.<source-extension>
└── thumbnail/<id>.jpg
```

数据库只保存相对路径。资料库、月历、时间轴优先解码适配尺寸并缓存的 thumbnail；详情页和封面海报优先按目标尺寸采样 original，读取失败时回退到另一来源或主题化缺省封面。显示过程不会修改原图；替换或移除封面时才会清理被替换的应用内部文件。

## UI 与主题基础

界面通过 `AppTheme` 使用语义外观值，包括页面背景、卡片、对话框、文字层级、轮廓、导航、胶囊、月历单元和图片遮罩。页面容器统一消费一次状态栏 inset，主页面与二级页共享 44dp 标题栏、2dp 额外顶部间距、6dp 内容间距和 40dp 操作区。

详情页只负责展示；新增/编辑页负责修改，并在存在未保存内容时拦截系统返回操作。已有记录支持点击或长按进入同一个编辑底部弹窗。详情记录按日期倒序显示，共用一张外层卡片并以留白和弱分隔线区分。

首页月历日期封面区域统一为 5:6，内部封面统一为 2:3；两至四张均采用固定方向的轻微错位层叠，按 `record.created_at`、Record ID 和 Activity ID 稳定排序，最新封面位于最前。时间轴使用固定 56×84 dp 封面，资料库网格与列表使用固定 2:3 槽位；详情页按原始比例完整显示封面。

首页主体为固定高度时间轴与更高 z 轴月历浮层。时间轴只保留收起月历的固定顶部 padding；月历展开部分直接覆盖列表，因此展开、收起和进入独立年历路由都不会用动态 padding 推挤时间轴。月历长期状态只有收起与展开；`AnchoredDraggable` 的 excess delta 进入独立阻尼 overdrag，局部 nested-scroll 协调回拉与释放，达到阈值后只发送一次全年导航事件。

资料库顶栏可将当前筛选结果导出为固定网格海报。每个海报单元是 2:3 画布：底层用同一原图居中裁切、降采样模糊并降低对比度，上层用原图完整居中适配，不裁切、不拉伸，也不提供用户裁切或焦点设置。
